= Tutorial 1: Fork and preview the lab guide
include::partial$_attributes.adoc[]

ACME starts by making its own copy of the workshop: it forks the three repositories, points the
copies to each other, and looks at the lab guide on a local computer.

[cols="1,3"]
|===
| Goal | Your forks of the three repositories, and the lab guide running locally in your browser
| You need | A GitHub account or organisation, `git`, and either `podman` or Node.js 20 or later;
the shell variables from the xref:index.adoc#_your_values[Introduction]
| Time | about 20 minutes
|===

== Step 1: Fork the three repositories

Fork these repositories into your GitHub account or organisation (`$GITHUB_ORG`). Keep their
names.

* {GITOPS_REPO_URL}[`{GITOPS_REPO}`^]
* {GUIDE_REPO_URL}[`{GUIDE_REPO}`^]
* {CODE_REPO_URL}[`{CODE_REPO}`^]

[tabs]
====
GitHub web::
+
--
Open each repository, click *Fork*, choose your account or organisation as *Owner*, keep the
*Repository name*, and click *Create fork*.

== Step 2: Clone your forks

[source,bash,subs="attributes+"]
----
mkdir -p "$WORKDIR" && cd "$WORKDIR"
for repo in {GITOPS_REPO} {GUIDE_REPO} {CODE_REPO}; do
  git clone "https://github.com/$GITHUB_ORG/$repo.git"
done
----

== Step 3: Point the forks to each other

The three repositories refer to each other, and to the image of the lab guide. In your forks,
these references still point to the original workshop:

[cols="2,3"]
|===
| Reference | For example in

| the gitops repository, which Argo CD installs from | `bootstrap.sh`, `argocd/application.yaml`,
`charts/workshop/values.yaml`
| the code repository, which every workspace clones | `charts/workshop-users/values.yaml`,
`charts/workshop-platform/values.yaml`, the lab guide's `_attributes.adoc`, the code repository's
`devfile.yaml`
| the lab guide image | `charts/lab-guide/values.yaml`
| links in the READMEs and `CLAUDE.md` files | all three repositories
|===

Replace them all at once. The commands leave out the `docs/` folder of the gitops repository,
which records the workshop's history:

[tabs]
====
macOS::
+
--
[source,bash,subs="attributes+"]
----
cd "$WORKDIR"
for repo in {GITOPS_REPO} {GUIDE_REPO} {CODE_REPO}; do
  (cd "$repo" && git grep -l -e 'github.com/{GITHUB_UPSTREAM}/' \
      -e 'githubusercontent.com/{GITHUB_UPSTREAM}/' -e '{GITHUB_UPSTREAM}.github.io' \
      -e 'quay.io/{GITHUB_UPSTREAM}/inner-outer-loop-lab' -- ':!docs' \
    | xargs sed -i '' \
        -e "s|github.com/{GITHUB_UPSTREAM}/|github.com/$GITHUB_ORG/|g" \
        -e "s|githubusercontent.com/{GITHUB_UPSTREAM}/|githubusercontent.com/$GITHUB_ORG/|g" \
        -e "s|{GITHUB_UPSTREAM}.github.io|$GITHUB_ORG.github.io|g" \
        -e "s|quay.io/{GITHUB_UPSTREAM}/inner-outer-loop-lab|quay.io/$QUAY_USER/inner-outer-loop-lab|g")
done
----

== Step 4: Commit and push

[source,bash,subs="attributes+"]
----
for repo in {GITOPS_REPO} {GUIDE_REPO} {CODE_REPO}; do
  git -C "$repo" commit -am "Point the fork to $GITHUB_ORG" && git -C "$repo" push
done
----

== Step 5: Preview the lab guide

Start a local preview of your lab guide:

[tabs]
====
Podman::
+
--
[source,bash,subs="attributes+"]
----
cd "$WORKDIR/{GUIDE_REPO}"
podman run --rm --name antora -v "$PWD:/antora" -p 8080:8080 -it ghcr.io/juliaaano/antora-viewer
----

The viewer builds the site and serves it on port 8080. It rebuilds when you save an `.adoc` or
`.yml` file; reload the browser to see the result. Stop it with kbd:[Ctrl+C].

On Linux with SELinux, add `:z` to the volume: `-v "$PWD:/antora:z"`.
--
Node.js::
+
--
[source,bash,subs="attributes+"]
----
cd "$WORKDIR/{GUIDE_REPO}"
./build-site.sh
python3 -m http.server -d www 8080
----

`build-site.sh` downloads Antora with `npx` the first time, then builds the guide in three
variants (`www/` is the whole workshop). Run it again after every change, and stop the web
server with kbd:[Ctrl+C].
--
====

Participants open the lab guide with their own values in the URL. Open the preview with
example values:

[source,text]
----
http://localhost:8080/?OPENSHIFT_USERNAME=user1&OPENSHIFT_PASSWORD=openshift&OPENSHIFT_CONSOLE_URL=console-openshift-console.apps.cluster.example.com&OPENSHIFT_API_URL=api.cluster.example.com:6443
----

== Optional: preview your lab guide on GitHub Pages

The lab guide repository publishes every push to `main` on GitHub Pages
(`.github/workflows/gh-pages.yml`). In a fork this is switched off. To use it, in your fork of
`{GUIDE_REPO}` on GitHub:

. *Actions*: allow the workflows of the fork.
. *Settings → Pages*: set *Source* to *GitHub Actions*.
. Push a commit, or run the workflow *github pages* by hand.

The guide is then at `\https://$GITHUB_ORG.github.io/{GUIDE_REPO}`. Add the URL parameters above
to see per-user values.

== Troubleshooting

[cols="2,3"]
|===
| Problem | Solution

| `sed: 1: "...": invalid command code` | You used the Linux command on macOS. Use the *macOS* tab
(`sed -i ''`).
| `sed: can't read ...: No such file or directory` | You used the macOS command on Linux. Use the
*Linux* tab.
| The check in step 3 still finds `github.com/{GITHUB_UPSTREAM}` | `GITHUB_ORG` was empty when you
ran the commands. Set it (see the xref:index.adoc#_your_values[Introduction]) and run step 3 again.
| The page shows `%openshift_username%` instead of `user1` | Open the preview with the URL
parameters, as shown in step 5.
| `address already in use` on port 8080 | Another program uses the port. Use another one, for
example `-p 8081:8080` (Podman) or `8081` (Node.js), and the same port in the URL.
| `Cannot connect to Podman` on macOS or Windows | Start the Podman machine:
`podman machine start`.
|===
